# design-slide

ユーザーが学んだ概念を、あとで見返せる1枚のスライド（SVG + PNG）にして `docs/design/` に置く。

## なぜこのスキルがあるか

ユーザーは Database Internals などを読みながら、ufodb の設計の参考にするために概念を整理している。
チャットでの説明は流れて消えるので、納得できた説明だけをスライドとして残している。
スライドは「読んだ本の要約」ではなく、「ユーザーがつまずいた点と、それが解けた説明」の記録である。

## 進め方

1. **先にチャットで説明する。** スライドは、ユーザーが説明に納得して作成を頼んだときに作る。頼まれていないのに作らない。
2. **会話でユーザーに通じた説明をそのまま使う。** ユーザーが自分の言葉で言い直した理解や、誤解していた点は、スライドの中心に置く。会話に出ていない話題を足さない。
3. **ufodb に触れるなら、書く前にコードを読む。** たとえば「いまの storage.rs は…」と書くなら、その時点の `src/storage.rs` を読んで確かめる。存在しないコマンド名や古い仕様を書かないため。
4. `assets/template.svg` を土台にして `docs/design/<名前>.svg` を書く。名前は内容を表す英語のケバブケース（例: `storage-layers`、`hdd-vs-ssd`）。
5. `scripts/render.ps1` でPNGにする。
6. **できたPNGを Read で見て確かめる。** はみ出し、重なり、参照番号のずれ（「①の〜」が実際は②にある、など）、事実の誤りを探す。直したら再度レンダリングして見直す。
7. ユーザーに報告する。

既存のスライド（`docs/design/*.svg`）は、座標や文字サイズの実例として読んでよい。

## レンダリング

```powershell
powershell -File .claude\skills\design-slide\scripts\render.ps1 -SvgPath docs\design\<名前>.svg
```

SVGと同じ場所に、同じ名前のPNG（3200×1800）ができる。Edge か Chrome のヘッドレスモードを使う。

draw.io は使わない。READMEの図は draw.io で作っているが、スライドは文字が多く、SVGを直接書くほうが位置を細かく決められるため。

## スライドの形

- キャンバスは 1600×900。上にタイトルと「結論を1文で言ったサブタイトル」、下にパネルを並べる。
- パネルは3列が基本で、見出しに ①②③ を付ける。大きな図が主役のときは、左2列を1枚にまとめた2列構成にする。
- 1枚で言うことは1つにする。サブタイトルの1文に収まらないなら、スライドを分ける。
- 最後のパネルは、できれば「それが ufodb ではどうなるか」に当てる。ユーザーの目的は ufodb の参考にすることなので。関係が薄い話題なら無理に入れない。

## 色

色は意味で使い分ける。飾りでは使わない。

| 色 | 塗り / 線 / 文字 | 意味 |
|---|---|---|
| 青 | `#e3f2fd` / `#1565c0` / `#0d47a1` | 主役。DB側、いま説明しているもの |
| 濃い青 | `#1565c0` / `#0d47a1` / `#ffffff` | 青の中でさらに強調するもの（例: 根ノード） |
| グレー | `#eeeeee` / `#757575` / `#424242` | DBの外。OS、ディスクなど |
| オレンジ | `#fff3e0` / `#ef6c00` / `#e65100` | 例外、注意、追いかけてほしい1つの要素 |
| 赤 / 緑 | `#ffebee` `#c62828` / `#e8f5e9` `#2e7d32` | 遅い・速いなどの良し悪しの比較だけ |

同じものは図のどこでも同じ色にする。
たとえば「ページ2」をオレンジにしたら、それに当たるブロックもディスク上の位置もオレンジにする。
これで線を引かなくても対応が目で追える。

## 文字

- すべて日本語で書く。用語は会話で使ったものにそろえる。
- 1つの箱や行に書くのは短い1文まで。長い説明はチャットに残し、スライドには結論だけ載せる。
- 例は具体的にする（`alice`、「7番ページ」、「8KB」）。同じスライドの中では同じ例を使い回す。
- 目安の数値（「約10ms」など）を載せたら、報告のときに「目安の値」と伝える。
- 文字サイズの目安: タイトル44、サブタイトル22、パネル見出し24、箱の名前22、箇条書き20、箱の中の説明16〜18、補足17。
- SVGの文字は自動で折り返さない。幅は「全角1文字 ≒ フォントサイズ、半角1文字 ≒ フォントサイズの0.55倍」で見積もり、箱の幅に収まるか書く前に計算する。収まらないなら文を短くする。

## 報告

報告は短くする。

- PNGとSVGへのリンク
- 各パネルに何を書いたかを1行ずつ
- 会話の説明から変えた点、省いた点があればその理由
- 自分で判断したこと（ファイル名、列の構成など）

`README.md` や `docs/` の他のファイルからのリンクは、頼まれたときだけ張る。
